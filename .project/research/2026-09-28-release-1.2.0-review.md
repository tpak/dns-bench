# Pre-release review of v1.2.0

- **Date:** 2026-09-28 (fixes applied 2026-09-29)
- **Question:** Before tagging v1.2.0 (Phases 2–7), are the release notes accurate and complete for
  someone upgrading from 1.1.0, do upgrading and going back work, and does anything the notes promise
  fail in practice?

## Method

A first workflow of five long-running reviewers never finished: its agents were interrupted and
restarted repeatedly for about two hours. It was stopped, and replaced by 14 small, time-boxed checks,
each followed by an adversarial verifier and then a completeness critic. There were 58 agents in all,
with no errors. The checks were: the notes section by section (Upgrading/Added, Changed ×3,
Fixed/Security), compatibility (CLI, web API, web UI, run files, config and packaging), a real upgrade
by `git pull` from v1.1.0 in a scratch clone, the release mechanics, a wheel install, and the docs and
browsers.

Result: 39 findings confirmed, 4 refuted. The critic added four gaps nobody had tested.

**Lesson:** give review agents one narrow question and a time box. Long, broad agents were the ones
that kept getting interrupted.

## Critic's untested gaps

| Gap | Outcome |
|---|---|
| `serve --host 0.0.0.0 --allow-remote` answered 403 to every other machine: the Host check only accepted loopback names, and `0.0.0.0` added nothing | **Real bug.** When bound to every interface, the server now also accepts a `Host` that is an IP address literal. Host names are still refused, because DNS rebinding needs one. Tests cover IPv4, IPv6, names, look-alike names and the wrong port, and a POST whose `Origin` is that IP. |
| No live DNS run of the candidate | Done before this review's fixes: default config, `--rounds 1`, scratch home. |
| No real-browser check under the new CSP | Chris clicked through it in his browser. |
| System detection on Linux never ran live | New CI step on ubuntu and macOS: `config --detect` into a scratch config. |

## Decision/recommendation

Release 1.2.0 with the rewritten notes. Before future releases, run the same small-checks review. A
real `git pull` upgrade in a scratch clone found the most important issues.
