# Decisions

Append-only. One line per decision: `YYYY-MM-DD: [Topic] [Decision] — [Rationale].` Never edit a past entry; to reverse one, append a new entry that references it.

2026-09-27: [Release] Tagged the one-shot generated version as v1.0.0 — a fixed baseline before the remediation work in REMEDIATION_PLAN.md starts changing things.
2026-09-27: [Python] Raised the minimum Python from 3.9 to 3.13 — uv can supply any interpreter, 3.9 is past end-of-life, and the code needs nothing older; 3.13 is the owner's default interpreter and gets security fixes until October 2029.
2026-09-27: [Tooling] uv manages Python interpreters, environments and tools; pyenv, pip and pipx are not used — one tool, the same one the owner uses on other machines.
2026-09-27: [Dependencies] The runtime stays standard-library-first, but third-party packages are allowed when justified — the README's "no pip install" promise is no longer a hard constraint.
2026-09-27: [Plan] Lint/format (Phase 0) and CI (Phase 1) come before the remediation phases — every later change is then linted locally and tested in CI from its first commit.
2026-09-27: [Lint] Ruff lints and formats Python; Biome lints and formats JS, CSS and JSON; pre-commit runs both on every commit — one fast tool per language, and no Node packages in the repo (pre-commit fetches Node for the Biome hook itself).
2026-09-27: [Lint] Ruff uses an explicit rule list (E, W, F, I, B, UP, SIM, A, RUF), not its defaults — a ruff upgrade can't silently change what is checked.
2026-09-27: [Lint] Tool versions are pinned in .pre-commit-config.yaml, not as uv dev dependencies — no pyproject.toml/uv.lock is needed before Phase 2 packaging, and CI can run the same pinned hooks.
2026-09-27: [Lint] Biome's noDescendingSpecificity is off — its fixes reorder CSS rules, which can change which rule wins; revisit with a visual check (REMEDIATION_PLAN.md Phase 7).
2026-09-27: [JSON] Untrusted JSON (the config file, API request bodies) goes through config.loads_json, which rejects nesting deeper than 32 levels — Python 3.14's parser accepts nesting that 3.13's rejects, so the limit lives in code; the two tests the plan expected to relax were right and stay unchanged.
2026-09-27: [Tests] The rate-limit tests check the sleeps the runner requests, not measured wake-up times; real-time bounds keep only 0.5 s of slack for stalls — CI's macOS runners wake threads 60–130 ms late, and the requested sleep is exact.
2026-09-27: [CI] A single gate job, `ci-passed`, is the check branch protection requires — its name doesn't change when the test matrix does.
2026-09-27: [CI] Actions are pinned to commit SHAs, and a pin is at least 7 days old: setup-uv v10.1.0, not the 6-day-old v10.2.0; Dependabot's monthly grouped updates use a 7-day cooldown — time for a compromised or broken release to be noticed.
2026-09-27: [Release] release.yml re-runs ci.yml through workflow_call, and run by hand it is a dry run that publishes nothing — one definition of the checks, and a way to preview the release notes before tagging.
2026-09-27: [Versioning] A higher minimum Python is a minor version bump — it changes what users must install, not their config or run files (README "Releasing").
2026-09-27: [Release] release.yml publishes only commits that are on main (GitHub compare API), checked on tag pushes and on dry runs of main — the tag-name check alone would have released a tag pushed from an unmerged branch.
2026-09-27: [Web UI] The web UI's minimum browsers are Chrome/Edge 93, Firefox 92 and Safari 15.4 (ES2022, via Phase 0's lint fixes), documented rather than reverted — a localhost UI opened in the user's own, current browser.
2026-09-27: [Versioning] Released 1.1.0 (minor: the minimum Python rose to 3.13).
2026-09-27: [Packaging] pyproject.toml builds with hatchling and reads the version from dnsbench.__version__ — uv's own backend (uv_build) rejects a dynamic version, and __version__ stays the one place a release bumps (release.yml checks it). hatchling is needed only to build; the runtime still has no dependencies.
2026-09-27: [Packaging] Only editable installs are supported (`uv tool install --editable .`) — config.json and runs/ live in the checkout, so the command must run the checkout's code; Phase 4 makes a non-editable install fail with a clear message.
2026-09-27: [Types] mypy runs as a pre-commit hook (mirrors-mypy v2.3.1, pinned like ruff and Biome, so CI runs it too), over all of dnsbench/ and tests/ rather than the staged files, with default settings — a change in one module can break another, and lenient settings let it land with behaviour-preserving fixes only; Phase 6 tightens it.
2026-09-27: [Tests] Two real run files from 1.0.0, with the hostname, ISP IPs and a personal domain replaced, are test fixtures (tests/fixtures/runs-v1), and Biome skips tests/fixtures — they pin the on-disk run format for Phase 6's migrate(), and a formatter would rewrite them.
2026-09-27: [Server] Every request except GET and HEAD must have no Origin or the server's own (http://<Host>); two Host or Origin headers are refused — pages can't forge or drop Origin, and curl/scripts send none, so this blocks cross-site pages without an auth scheme.
2026-09-27: [Server] The UI's CSP drops 'unsafe-inline' for styles and adds require-trusted-types-for 'script' plus trusted-types 'none' — app.js styles only through CSSOM and uses no HTML sinks, verified in headless Firefox, which enforces both.
2026-09-27: [Server] serve refuses a non-loopback --host unless --allow-remote is given, and the README recommends an SSH tunnel — the UI has no authentication.
2026-09-27: [Limits] At most 20 resolvers and 50,000 queries per run (enabled servers x domains x rounds), re-checked after a rounds override — bounds threads, run time, run-file size and what the UI draws; the defaults send 480.
2026-09-27: [Runner] Every server is measured at once and max_parallel_servers is removed (ignored in old configs) — batches timed servers in different windows, which made them incomparable; per-server pacing still bounds the load.
2026-09-27: [Runner] A crashed run is returned and saved with status "partial" and an "error" field, not re-raised — the queries already measured are kept, as for a cancelled run.
2026-09-27: [Storage] storage.save_run_safely (save, or rescue to the temp dir) is shared by the CLI and the web UI — the UI used to lose a finished run on a save error; Phase 6 moves it into the service layer.
2026-09-27: [CLI] SIGTERM is handled like Ctrl-C (exit 130); a second signal stops waiting for queries in flight; signals during the save are ignored — every way of stopping a run keeps what was measured.
2026-09-27: [Tooling] Visual UI checks use headless Firefox screenshots, not headless Chrome — Chrome hangs on this machine even outside the sandbox; see .project/research/2026-09-27-headless-browser-ui-check.md.
2026-09-28: [Data] config.json and runs/ are untracked and created on first use (a saved run, `serve`, a Settings save or reset, `config --reset/--detect`); loading never writes — the UI rewrote a tracked file, and a GET /api/config could create one (ARCH-4, MNT-1). Users who changed config.json move it aside while pulling the commit that untracks it: git refuses that merge otherwise (tested); the CHANGELOG has the commands.
2026-09-28: [Defaults] The hard-coded ISP resolver is replaced by a "System" entry detected from the OS (scutil --dns; /etc/resolv.conf, or systemd-resolved's upstream file behind the 127.0.0.53 stub; loopback stubs skipped), written into the config when it is created or reset and never re-detected per run — other users saw the author's ISP as unreachable (MNT-9), and per-run detection would mix two networks' resolvers under one name.
2026-09-28: [Paths] Data stays in the checkout; DNSBENCH_HOME moves it, --config/--runs-dir override each path, and outside a checkout (a non-editable install) resolving fails with a message asking for DNSBENCH_HOME — no guessing a location, in line with the editable-only packaging decision.
2026-09-28: [API] GET /api/info (version, paths) and POST /api/config/system-resolver (a System entry for the Settings draft, which the user saves like any other edit) — the server de-duplicates detected servers against the draft with the same server_key rules as validation, so the UI copies no rule.
2026-09-28: [Validation] Config errors are ValidationError(path, code, message) from one validator per section; str() keeps the CLI's sentence, ConfigError adds the file only for the CLI, and API details are [{path, code, message}] with no file paths or exception text — the UI places errors by path instead of parsing prose (classifyServerError), and one message serves both (SEC-8, ARCH-8).
2026-09-28: [API] The web UI takes every rule from GET /api/schema, has drafts checked by POST /api/config/validate (debounced) and estimates made by POST /api/estimate; app.js keeps only presentation (labels, help text) — its copies of the defaults, bounds, estimate and validation had drifted (ARCH-1, MNT-3, FE-4). /api/config responses become {config, errors, estimate}, and /api/defaults is removed (the schema has the defaults).
2026-09-28: [Web UI] Settings sends the draft as typed (servers and domains as text, numbers as strings) and the server normalises it; "unsaved changes" compares the form with the form built from the saved config — no client-side normaliser to keep in step with config.py.
2026-09-28: [Tooling] Interactive UI checks run a copy of the UI with an injected test script in headless Firefox, which reports DOM state back through a patched static route — no WebDriver, Selenium or Node needed; see .project/research/2026-09-27-headless-browser-ui-check.md.
2026-09-28: [Architecture] Three layers under the front ends: storage.RunRepository only reads and writes run files (migrate() on every load; typed RunNotFound, NoRuns, CorruptRun), analysis.Analysis recomputes each run's summary and recommendation on load (cached per file by mtime, size and ANALYSIS_VERSION, in the object, not the process), and service.BenchmarkService (prepare, execute, persist) with JobManager is the one run path for the CLI and the web UI — every view uses the current analysis, and the UI shares the CLI's checks, save and rescue (ARCH-2, ARCH-3, MNT-11, MNT-18).
2026-09-28: [Run files] Format 1 is the 1.x format plus schema, kind and a per-row truncated flag; migrate() reads a file without schema as 1, fills the new row fields and drops stored summary/recommendation. New files still store them, plus analysis_version, as a snapshot for other tools — never read back.
2026-09-28: [Recommend] recommend() is rank → choose → explain; notes are {code, params, text} with the text written in Python; the score formula is one string generated from the weights (SCORE_FORMULA), used by the text report and checked against the README by a test.
2026-09-28: [Types] mypy checks the core modules strictly (config, stats, recommend, report, models, storage, analysis, service, paths, sysdns: every def annotated, generics spelled out, no Any returns); cli, server, runner, resolver and tests keep the lenient defaults — the front ends are thin adapters now, and TypedDicts make the record shapes checkable where they are computed.
2026-09-28: [Tests] tests/samples.py holds sample runs shared by several test modules, imported as `samples`; run one module with `discover -s tests -p <file>` — one copy of make_run instead of four.
2026-09-28: [Web UI] app.js stays one file (the owner's call) but draws through one rAF-batched scheduleRender(parts, after); actions change state and ask for a redraw, view builders only read state, and view-to-DOM handles live in viewHooks — FE-1 within a single file, without a framework or a build step.
2026-09-28: [Web UI] Focus: actions that redraw put the keyboard back on their own control (state.focusAfterRender); a tab change focuses the tab panel (the APG tabs pattern) rather than a heading, except when the arrow keys are moving along the tabs; charts use a roving tabindex — FE-3, FE-10.
2026-09-28: [CSS] Biome's noDescendingSpecificity is on again; eleven rules were reordered and one pair (the domain detail's table vs the heat table, which never match the same element) carries a biome-ignore — verified by byte-identical screenshots of every view in both themes before and after (supersedes the 2026-09-27 entry that turned it off).
2026-09-28: [Tooling] Visual regressions are checked by hashing headless-Firefox screenshots of every view in light and dark from fixed data — rendering is deterministic, so a CSS change meant to be invisible must leave every hash unchanged.
2026-09-29: [Versioning] 1.2.0 stays minor although its new limits (20 resolvers, 50,000 queries per run) reject some configs 1.1.0 accepted — only outlier configs are affected, the file format is unchanged, nothing is rewritten, the run stops before sending queries with a message naming the limit, and the notes say how to fix it under Upgrading. The README policy ("major for changes that break existing config.json") read literally says 2.0.0; Chris asked for 1.2.0.
2026-09-29: [Server] Bound to every interface (`serve --host 0.0.0.0/:: --allow-remote`), the Host check also accepts any IP address literal — other machines can only reach it by one of this machine's addresses, which can't all be listed; host names stay refused, since DNS rebinding always goes through a name.
